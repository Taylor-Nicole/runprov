# The cross-version record corpus

**Records produced by the real released wheels, kept so that today's package can be held to
them.** Not written by hand, not reconstructed from the current record shape, not generated by
the code under test — each tree came out of `pip install runprov==<version>` from PyPI.

## Why it exists

Every other test in this project builds a record with the same code that reads it. That leaves
one failure invisible, and it is the failure a provenance package must never have: **a record
written last year that this year's version reads differently, or refuses.**

It is not hypothetical. Audit C found `sha256_tree` had silently *changed* on Linux and macOS
inside a fix meant to make it machine-**in**dependent — so every directory input pinned by
0.1.0 through 0.4.0 would have verified STALE with nothing on disk touched — and the suite was
green through all of it, because the suite had no record older than itself. Four more defects
across the two audits had the same shape. Thirty agents found those. This finds them on every
commit, in a few seconds.

## Layout

```
MANIFEST.json          which versions, when captured, and the sha256 of the scenario used
<version>/tree/        the captured project, exactly as that version wrote it
  data/                the scenario's inputs — byte-identical in every version
  out/*.tsv            the artifacts, WITH their pins, copied byte for byte
  prov/                history, sidecars, YAML twins, the environment snapshot
  scenario.json        which optional API the scenario could use on that version
```

## Two rules

**The artifacts and the environment snapshot are never edited.** The artifact carries the pin
whose body digest `verify` re-derives, and the snapshot's *filename is the digest of its body*.
A corpus that had to be rewritten to be moved would be measuring the rewriter. Only
`prov/*.json`, `prov/*.jsonl` and `prov/*.yml` are normalised, and only to replace this
machine's absolute root with `@@RUNPROV_CORPUS_ROOT@@` — nothing digests those files.

**`data/refs` is a directory on purpose, and its three subdirectory names are chosen rather
than illustrative.** `panel/`, `panel.old/` and `panel-v2/` sort in *opposite* orders depending
on whether the key is the rendered string or the path's parts, because `/` is 0x2f while `.` is
0x2e and `-` is 0x2d. That is exactly the quantity C-03 moved. Flat filenames sort identically
under both keys, so a corpus built from those alone would *look* like it covered the defect it
was built for and would not.

## Regenerating

Needs the network; the corpus is committed, so the gate itself is offline.

```bash
python tools/corpus.py generate --all      # every released tag
python tools/corpus.py generate --version 0.5.0
python tools/corpus.py verify              # is the corpus honest? also `python ci.py corpus`
```

Editing `tools/corpus_scenario.py` **requires regenerating**: the manifest records the
scenario's sha256 and a test compares it, because otherwise every assertion here keeps passing
while describing a scenario that no longer exists.

A released version that is never captured is caught by the suite one release later — the grace
period is because the wheel has to reach PyPI before it can be installed.
